# 两段演示视频录制脚本

状态：脚本已准备，视频尚未录制，暂无可交付视频链接。每段目标 4 分钟，允许 3–5 分钟。使用实际桌面 Unity 程序或 Editor Game 视图，配合 React 与 Go 终端录屏；如评审对“真机”另有拍摄要求，录制前确认。

## 录制准备

功能测试已由用户确认通过；录制前按 acceptance.md 快速复查。打开 Unity、Go 终端和 http://localhost:5173 管理端，准备窗口切换。确保录屏包含完整桌面切换而不是只捕获 Unity 单窗口，避免录不到浏览器和终端。先试录 15 秒并回放检查画面、中文、鼠标和声音；不要展示账号凭据或私人窗口。

每段使用不同标题，例如“演示A-机柜温度异常”和“演示B-水泵异响”，追加日期时间避免与历史记录混淆。摄制中保存同一条记录的完整 ID、坐标和状态，不依赖列表顺序判断。

## 视频一：正常业务闭环（约 4 分钟）

| 时间 | 操作与讲解 | 画面证据 |
| --- | --- | --- |
| 0:00–0:30 | 介绍 Unity 现场、Go 保存、React 处理；说明是桌面虚拟现场 | 三端窗口与同一后端地址 |
| 0:30–1:10 | WASD 走动，右键转向，查看两台机柜和水泵 | 实际移动与观察 |
| 1:10–2:00 | 点击设备表面，指出黄色球与命中坐标；填写 A 标题、描述、high 并提交 | 表单输入、成功提示和绿色标记 |
| 2:00–2:45 | 切到 React，刷新并查看详情，核对 ID、坐标 | 同一条问题，状态待处理 |
| 2:45–3:15 | 改为处理中，再改已解决；等待成功提示 | 状态实际保存 |
| 3:15–4:00 | 记下 ID，在 Go 终端 Ctrl+C 停止，再用原命令启动，React 刷新核对 | 同一 ID、坐标和已解决状态在重启后保留 |

讲解要点：坐标来自 Physics.Raycast 的 hit.point，球体的视觉偏移不写入 position；数据由 Go 持久化，前端不自行造记录。绿色球只表示上报成功，不代表已解决。

## 视频二：异常恢复与可解释性（约 4 分 30 秒）

第二段也包含一条独立的完整主流程，确保两段分别可理解。

| 时间 | 操作与讲解 | 画面证据 |
| --- | --- | --- |
| 0:00–0:30 | 移动到另一设备并点击表面 | 位置不同，黄色草稿出现 |
| 0:30–1:15 | 空标题提交，展示校验；点击输入区且按 WASD，取消，再点击新位置 | UI 不穿透、不移动；取消后草稿移除 |
| 1:15–2:10 | 在 Go 终端停止服务，填写 B 标题和描述后提交；切 React 刷新 | Unity 明确失败并保留输入；React 显示错误，不白屏 |
| 2:10–3:00 | 重启 Go，React 刷新先确认没有 B，再回 Unity 重试；React 刷新查看 | 没有重复记录；相同输入成功上报，ID/坐标一致 |
| 3:00–3:45 | B 改为已解决；再次停止并重启 Go，刷新确认 B 保留 | 真实状态保存与进程重启证据 |
| 3:45–4:30 | 展示 README 的 AR 问答及 AI_LOG 的实际纠错记录，说明关键代码和未实现项 | 不把普通 3D 称为真实 AR；不把 AI 自查称为本人审核 |

若实际超时或编译导致超过 5 分钟，排查后重新录制；不剪掉失败后伪造成功，也不以仅关闭网页代替 Go 重启。检查演示标题是否真的不存在再重试。
